## 1. 이 프로젝트는

## 3. 다른 컴퓨터에서 시작하기

### 3-1. 필요한 프로그램
- **Node.js LTS** (원래 PC: v24.18.0 / npm 11.16.0)
- **Git**
- (PPT 파일을 다시 만들 때만) **Python 3.11+** 와 `pip install python-pptx`
- (선택) VS Code + Claude Code

### 3-2. 코드 가져오기
**GitHub에 올린 뒤라면** (권장)
```bash
git clone https://github.com/shinyk84/<레포이름>.git
cd <레포이름>
```

**아직 GitHub에 안 올렸다면** — `handson-app` 폴더를 USB·클라우드 드라이브로 복사하되, 아래 폴더는 빼도 됩니다(용량이 크고 다시 만들어짐).
- `node_modules/`, `.next/`, `dist/`
- `.data/` — 로컬 테스트 데이터. 옮기지 않으면 새 PC에서는 빈 상태로 시작합니다.

`.git/` 폴더는 꼭 함께 복사하세요(커밋 기록).

## 4. 배포 (아직 안 함) — 순서 요약
1. GitHub에 Private 레포 생성 → 푸시
2. vercel.com → Add New → Project → 레포 Import
3. Vercel 프로젝트 → **Storage** 탭: **Neon**(DB) 생성·연결, **Blob**(파일, Public) 생성·연결 → 값이 자동으로 들어감
4. **Settings → Environment Variables**:
   - `SESSION_SECRET` — 32자 이상 임의 문자열
   - `ADMIN_PASSWORD` — 배포 사이트의 강사 비밀번호 (없으면 강사 로그인 불가)
   - `ANTHROPIC_API_KEY` — (선택) AI 버튼 직접 동작
5. **Redeploy**

주의: 원래 PC는 컴퓨터 이름이 한글이라 **Vercel CLI가 동작하지 않음** → 대시보드에서 진행.

## 5. 핵심 결정 사항 (왜 이렇게 만들었나)
| 결정 | 이유 |
|---|---|
| DB는 Neon(Postgres), 로컬은 PGlite 자동 전환 | 기수가 쌓여도 데이터를 계속 확인해야 함. Supabase 무료판은 미사용 시 일시정지됨. 로컬은 설치 없이 실행 |
| 파일은 Vercel Blob (브라우저에서 직접 업로드) | 동영상 업로드 시 Vercel 서버 용량 제한(4.5MB)을 피하기 위해 |
| 로그인은 자체 구현 (기수 + 입장 코드 + 아이디) | 이메일 없이 기수별 개인 아이디로 운영. 같은 아이디가 다른 기수에 있어도 됨 |
| 강사 계정은 1개, 비밀번호는 환경변수 | 가입 절차 없이 단순하게. 코드에 비밀번호를 쓰지 않기 위해 |
| 기수 종료 = 보관 (삭제 아님) | 종료 후에도 강사·수강생 모두 기록 열람 가능, 신규 가입만 막힘 |
| AI 키가 없으면 '프롬프트 복사' 모드 | 비용 없이도 수업 가능 + 수강생이 프롬프트 구조를 직접 보고 배움 |
| 수업 PT를 JSON 하나로 관리 | 웹 발표와 PPTX가 항상 같은 내용 |
| 수업은 4주, 워크스페이스는 6단계 | 매핑: 1주 1~3단계 / 2주 4~5단계 / 3주 5단계 / 4주 5~6단계 (`src/lib/workspace.ts`의 `WEEK_PLAN`) |

## 6. 자주 고칠 곳
| 하고 싶은 것 | 파일 |
|---|---|
| 수업 PT 내용 수정 | `src/content/week1~4.json` → PPT는 `npm run deck:pptx` |
| AI 버튼 프롬프트 수정 | `src/lib/prompts.ts` |
| 주차↔단계 연결, 단계 이름 | `src/lib/workspace.ts` (`STEPS`, `WEEK_PLAN`) |
| 각 단계 화면 | `src/components/workflow/Step*.tsx` |
| 학습자 홈 | `src/app/app/page.tsx` |
| 강사 화면 | `src/app/admin/` |
| DB 테이블 | `src/lib/db.ts` (`SCHEMA`) — 기존 데이터를 지우는 변경 금지, 컬럼 추가는 `ADD COLUMN IF NOT EXISTS` |

수정 후 확인: `npm run typecheck` → `npm run build`

## 7. 알려진 사항
- 개발 서버(`npm run dev`)는 페이지마다 첫 접속이 20~40초 걸리고, 맨 처음 요청에서 오류가 한 번 날 수 있음 → 새로고침하면 정상.
- 개발 서버를 두 개 동시에 켜면 같은 `.data` 폴더를 함께 써서 데이터가 꼬일 수 있음 → 하나만 켜기.
- 배포 사이트와 로컬의 데이터는 서로 별개임.
